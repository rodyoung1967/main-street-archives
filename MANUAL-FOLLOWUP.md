The **5 September 2026 audit** rechecked that list against current `main`, formal manual callouts in the source captures, current online-access routes, and `RESEARCH-STANDARD.md`. This dashboard points to those canonical drafts rather than duplicating long email bodies. **Every current immediate-action item that requires outreach now has a linked ready-to-send message with a recipient, subject and complete body.** No draft has been sent as of this amendment.

## What the audit found

The prior 37-item list had four problems:

1. it mixed **actionable human requests** with broad research programs;
2. it treated **conditional fallbacks** as if they should be done immediately;
3. it included **archive housekeeping** that is not historical research work;
4. it missed several formal manual callouts already preserved elsewhere in the repository.

The audit therefore uses these action classes:

- **ACTIVE MANUAL** — still needed and worth pursuing as a human/institutional action.
- **ACTIVE — COMBINE** — still needed, but should be sent as one combined request with another item rather than as separate correspondence.
- **CONDITIONAL / DEFER** — valid source target, but do it only if a higher-value or prerequisite route does not resolve the question.
- **YEAR-CLOSEOUT** — genuine manual gap required for eventual `ONLINE + MANUAL COMPLETE`, but not an immediate project priority.
- **ONLINE-FIRST** — do not assign to the user yet; reasonable public-online/restricted-digital recovery should be tested first.
- **MERGED / OUTCOME** — not a distinct request; the question is answered by other listed source requests.
- **HOUSEKEEPING** — repository preservation/ingest work, not a manual historical-research callout.
- **OPTIONAL / DESIRABLE** — useful corroboration, but not currently required to answer an active historical question or close a year.
- **CLOSED / RESOLVED** — completed or explicitly closed; retain for audit history only.

Sending a request is not completion. A source task becomes complete only after the reply/material is received, visually reviewed where applicable, and integrated, or the project steward explicitly closes it with a reason.
